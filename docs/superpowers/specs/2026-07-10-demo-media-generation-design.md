# 现场演示媒体生成设计

## 目标

在 `codex/demo` 分支中提供稳定、可重复的现场演示流程：保留现有笔记本聊天、AI 思考、资源推荐和生成配置界面；用户点击最终“确认生成”后，前端模拟视频或播客生成进度，并在预定时间结束后展示随分支提交的本地成品媒体。

本演示只替换视频和播客的实际生成过程。聊天回答及推荐链路继续使用现有实现。

## 不可违反的约束

- 视频确认生成后不得请求 `POST /api/studio/generate`。
- 播客确认生成后不得请求 `POST /api/podcasts/generate`。
- 演示流程不得触发任何豆包视频、播客脚本、语音合成或其他付费生成任务。
- 视频模拟耗时固定为 40 秒。
- 播客模拟耗时固定为 100 秒（1 分 40 秒）。
- 生成配置仅用于保持界面真实感；名称、预设、发言人、指令和素材选择均不传给生成后端，也不影响最终成品。
- 预生成视频和播客必须复制到 `frontend/public/demo-assets/` 并提交到 demo 分支，不能依赖 `data/` 目录或数据库中的媒体记录。
- 所有新增界面文案必须同时提供简体中文和英文翻译键。

## 方案选择

采用纯前端演示状态层，不新增演示后端接口，也不修改数据库记录。

未采用的方案：

- 后端虚拟任务：会增加 API、数据库和服务启动依赖，不利于现场稳定性。
- 修改现有数据库任务状态：依赖演示机当前数据，刷新、重置或重复彩排时容易失效。

纯前端方案直接从确认按钮进入本地任务状态，能够从结构上保证昂贵生成 API 不会被调用，并允许在前端独立测试整个计时过程。

## 状态模型

新增持久化的演示任务存储，每种媒体最多保留一个当前演示任务：

```ts
type DemoMediaType = 'video' | 'podcast'

interface DemoMediaTask {
  id: string
  type: DemoMediaType
  title: string
  startedAt: number
  durationMs: number
  assetUrl: string
}
```

任务仅保存开始时间和持续时间，不依赖长时间运行的单个 `setTimeout`。页面每秒根据 `Date.now() - startedAt` 计算剩余时间和完成状态，因此具备以下行为：

- 关闭生成动画后，计时继续。
- 跳转到其他页面后，计时继续。
- 刷新页面或浏览器标签页进入后台后，返回时根据真实经过时间恢复。
- 再次确认同类型生成时，替换旧任务并从头开始，方便重复彩排。

状态保存到浏览器本地存储。该状态只属于当前浏览器，不写入后端。

## 用户流程

### 视频

1. 用户在机器学习笔记本中正常发起对话。
2. AI 正常思考和回答，并返回视频资源推荐。
3. 用户点击推荐，沿现有链路进入 `/videos` 并打开预填充的视频生成弹窗。
4. 用户可以任意调整生成配置。
5. 用户点击确认生成。
6. 前端不构建生成上下文、不调用视频生成 API，直接创建 40 秒演示任务并关闭配置弹窗。
7. 视频工作区顶部出现可关闭的精美生成动画，同时列表顶部出现“生成中”的视频卡片。
8. 用户可以关闭动画或访问其他页面，任务继续计时。
9. 40 秒后视频卡片自动切换为“已完成”，点击后播放 `demo-assets/梯度下降.mp4`。

### 播客

1. 用户进入 `/podcasts`，点击生成播客。
2. 用户可以任意选择笔记本、节目模板、发言人和填写指令。
3. 用户点击确认生成。
4. 前端不构建生成上下文、不调用播客生成 API，直接创建 100 秒演示任务并关闭配置弹窗。
5. 播客工作区顶部出现可关闭的生成动画，同时列表顶部出现“生成中”的播客卡片。
6. 用户可以关闭动画或访问其他页面，任务继续计时。
7. 100 秒后播客卡片自动切换为“已完成”，音频控件播放 `demo-assets/机器学习与深度学习深度漫谈.mp3`。

## 生成动画

视频和播客共用一个紧凑的生成进度面板，显示：

- 媒体类型图标与任务名称。
- 柔和渐变光晕、脉冲环和三阶段流动节点动画。
- 根据真实经过时间计算的平滑进度条。
- “预计剩余时间”倒计时。
- 分阶段状态文案，例如“分析学习资料”“编排内容结构”“合成媒体成品”。
- 一个关闭按钮，以及明确的“关闭后仍将在后台继续”提示。

关闭仅隐藏动画面板，不取消任务、不清除列表中的生成中卡片。动画尊重系统的 `prefers-reduced-motion` 设置。

## 列表集成与媒体播放

现有 API 查询仍用于显示真实视频和播客记录。演示任务在前端合并到查询结果顶部，不写入 React Query 的后端响应，也不污染数据库。

- 进行中任务映射为现有组件能够识别的 `running` 状态。
- 到期任务映射为 `completed` 状态和固定本地资源 URL。
- 演示卡片使用稳定的 `demo-` 前缀 ID，避免与真实记录冲突。
- 演示任务不显示重试操作；删除演示卡片只清除本地演示状态，不调用后端删除 API。
- 真实记录继续使用原有查看、播放、重试和删除逻辑。

## API 隔离

演示判断位于两个确认处理器的最前面：

- 视频 `GenerateArtifactDialog` 在 `resourceType === 'video'` 时直接创建本地任务并返回。
- 播客 `GeneratePodcastDialog` 直接创建本地任务并返回。

该分支不提供关闭演示模式后回退到真实生成的运行时开关，避免现场误触付费 API。报告、测验、思维导图和 PPT 的现有生成行为不变。

## 错误与边界行为

- 本地存储不可用时，任务仍在当前页面内存中运行，但刷新后不恢复。
- 本地媒体加载失败时，卡片显示明确的“演示媒体不可用”提示，不回退到真实生成 API。
- 页面首次加载发现任务已到期时，立即显示完成状态，不重新播放完整倒计时。
- 浏览器系统时间变化可能改变剩余时间；剩余时间始终限制在 0 到配置时长之间。
- 用户关闭动画后，可以通过生成中卡片查看任务仍在进行。

## 测试与验收

### 自动化测试

- 计时函数在 0 秒、中间点和到期后返回正确状态、剩余时间及进度。
- 视频任务固定为 40 秒，播客任务固定为 100 秒。
- 刷新恢复时基于 `startedAt` 继续计时。
- 关闭动画不会删除任务。
- 视频确认路径不会调用 `studioApi.generate`。
- 播客确认路径不会调用 `podcastsApi.generatePodcast`。
- 演示任务与真实查询结果合并后位于列表顶部，删除演示项不调用后端删除接口。

### 构建与静态检查

- 运行前端相关 Vitest 测试。
- 运行 `npm run lint`。
- 运行 `npm run build`。

### 浏览器验收

- 从机器学习笔记本聊天推荐进入视频生成弹窗。
- 确认生成后看到动画和生成中卡片，网络请求中不存在 `/studio/generate`。
- 关闭动画并跳转页面，40 秒后返回可播放视频。
- 在播客页确认生成，网络请求中不存在 `/podcasts/generate`。
- 关闭动画并跳转页面，100 秒后返回可播放音频。
- 验证视频、音频控制条、完成状态、刷新恢复和重复生成。
